# Run an enterprise evaluation

Turn a product trial into a repeatable technical acceptance process.

## Agree the trial scope

- Record the assigned devices, phone models, OS versions, station location, trial dates, and named contacts.
- Choose the customer’s real workflow and the expected outcome for each step.
- Agree evidence for success: connection reliability, screenshot latency, action completion, observed task success, and recovery behavior.
- Set customer-specific targets before measurement. This documentation does not assert a generic uptime or latency SLA.

## Exercise the complete lifecycle

| Area | Acceptance exercise |
| --- | --- |
| Access isolation | Try an unassigned device and confirm denial without exposing its image or receipts. |
| Developer setup | A new engineer follows the docs and connects via REST and MCP. |
| Physical workflow | Run the agreed task, wait for receipts, and verify actual screen outcomes. |
| Recovery | Test network interruption and station restart in an operator-supervised session. |
| Access lifecycle | Verify renewal continuity, expiry, revocation, and new-key recovery. |
| Multi-device operation | Run independent workers on separate assigned devices and measure USB/camera/host capacity. |

## Prepare for fleet purchase

Confirm hardware quantities, tested station capacity, supported phone fixtures, installation ownership, spare-parts handling, software update policy, support coverage, and data-handling responsibilities. Record anything that remains a planned capability instead of treating it as an existing product guarantee.
